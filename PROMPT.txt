膜分离设计需要一个反渗透渗透压与回收核算的常驻服务，围绕具名工况档来组织：调用方要么点名一份已登记的工况档让服务按档计算，要么临时构造一份档提交。服务的职责限定在渗透压与产水回收这套膜过程内核，仅经 HTTP 对外提供，无需前端页面，也不是水费账单或水务工单。

渗透压依 van't Hoff 关系计算：π = i·C·R·T，其中 C 是摩尔浓度，i 是范特霍夫因子（对 NaCl 取 i=2），温度 T 必须为正，气体常数固定。允许改以质量浓度加摩尔质量的方式给出，但换算出的摩尔浓度必须与直接给的摩尔浓度自洽。浓度为负、温度不为正、因子不为正都要拒绝。要内置一份苦咸水工况档，它的渗透压应落在几个巴的量级，服务启动后可以点名这份档把结果打出来对照。

膜侧的净推动力为 NDP = Δp − Δπ，浓差极化可以只用一个薄的极化因子表达。产水流量按 Qp = A_mem·Lp·NDP 计算，渗透系数取工况档里登记的值。回收率 Y = Qp / Qf 落在开区间 (0,1) 之内。在盐截留率接近一的极限下浓水浓度为 Cb = Cf / (1 − Y)；若给出小于一的盐截留率，则产水带盐，全系统必须满足物料守恒：进料的盐量等于产水盐量加浓水盐量。回收率不小于一，或工作压差已低于进料渗透压却仍报出正的产水通量，都属于非法，要以带原因的错误返回。这里最凶险的错误是把浓水浓度写成 Cf·(1−Y)——那会让回收越高浓水反而越稀，盐守恒也随之崩坏，服务绝不能犯。

要守住的交叉关系有：只升高温度，渗透压上升，同一压差下净推动力下降；只提高回收率，浓水浓度上升；盐截留率取一时产水含盐为零、盐全部进入浓水；工作压差恰好等于进料渗透压且无极化时产水流量为零。全流程的渗透压、压差单位要统一，不允许在渗透压与压差之间偷偷来回换算量纲。

工况档的登记与取用、渗透压计算、膜通量与盐衡算、物料守恒校验、输入合法性检查要拆成彼此独立的模块，并附自动化测试，重点盯住压差低于渗透压时不得出现正通量，以及进料盐量等于产水加浓水盐量这条守恒。同一进程里两份不同工况档的计算结果必须各自独立，不得串到对方名下。

语言选 Go 1.22，HTTP 层用标准库 net/http 或 Gin 都可以。部署上给出一个 Dockerfile 即可，构建出的容器对外暴露一个固定端口的接口，配套测试打包在仓库里、在容器内能跑通。源码按包切开：渗透压、膜通量、工况档、校验、接口各自独立成包与文件，避免把逻辑全塞在一处。
